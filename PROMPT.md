# Мастер-промт для агента — подбор blur-затухания в Gradient Lab

> Скопируй агенту целиком. Версия 2 (2026-10-10) — под текущий инструмент:
> warnings, analysis?target, residuals/verdict, blur.rect/gradient/underlay, слои с rect, журнал.

```text
Ты подбираешь blur-затухание / градиентную маску в песочнице Gradient Lab
(~/its/gradient-lab, dev-порт 5180). Действуй СТРОГО по порядку.

ШАГ 0 — ДОКУМЕНТЫ (обязательно, до любых действий).
Прочитай ПОЛНОСТЬЮ ~/its/gradient-lab/API.md — включая раздел
«Методика подгонки» (выверена на живой сессии). Шпаргалка скилла gradient-lab
неполна: таргеты анализа, маркеры, альфа-стопы, журналы живут только в API.md.

ШАГ 1 — СЕРВЕР. `curl -sf localhost:5180/api/schema` — если упал:
`cd ~/its/gradient-lab && (npm run dev > /tmp/gradient-lab-dev.log 2>&1 &)`.

ШАГ 2 — МАТЕРИАЛ (ошибка здесь фатальна).
Ровно два кадра ОДНОГО момента анимации, кроп обоих ОДНИМ прямоугольником
(оптимум для краёв экрана — правый/левый квадрат по высоте + запас):
  • base  = блок БЕЗ эффекта (чистый экспорт);
  • ref   = блок С эффектом (из макета).
Все посторонние затемнения/градиенты запеки в ОБОИХ кадрах одинаково — тогда
попиксельный дифф = чистый эффект. Масштаб экспорта учти: пиксели лабы =
физпиксели макета, CSS = /scale (по умолчанию 2x), state.export в стейте.
Альтернатива: Figma-нода — вытащи заливки через figma MCP и задай параметры
вручную (медленнее, чем дифф двух кадров).

ШАГ 3 — СТАРТ. `GET /api/state` (404 → шаблон «Минимальный валидный BlockState»
в API.md, или пресет: `GET /api/presets` — там приёмы onsport). Положи кадры:
base.image и compare.refImage (dataURL), compare.x/y=0, scale=1, w/h блока =
точный аспект кропа. `PUT /api/state` (только полный стейт, read-modify-write).

ШАГ 4 — БОРТ-КОНТРОЛЬ. `GET /api/warnings` — исправь ВСЕ warn ДО подгонки:
аспект-кроп (примени fix {w,h} из предупреждения), трансформ/аспект референса,
«зона blur не накрывает переходы» (двинь blur.rect), дубли стопов, нулевой
радиус. Повторяй до пустого списка или только info.

ШАГ 5 — ГЕОМЕТРИЯ ЗОНЫ НЕ НА ГЛАЗ. Дифф кадров вне лабы:
`convert base.png ref.png -compose difference -composite -colorspace Gray -resize 'Wx1!' txt:`
— колонковый профиль: onset (>8% max) и near-full (>90% max) = границы зоны.
blur.rect ставь по ним и ЦЕЛИКОМ ВНУТРИ блока (за краем канва анализа
сэмплирует прозрачность — у кромки появится фальшивая ошибка).

ШАГ 6 — ЦИКЛ ПОДГОНКИ (без взгляда на UI):
  GET /api/analysis?target=<таргет эффекта>   // blurMask | blurBg | underlay | layer:N | blockMask
  Первый ответ может быть 404 {"requested":...} — полли раз в ~1с, пока target
  в ответе не совпадёт с запрошенным (нужна открытая вкладка — SSE).
  Читай: zoneMatchPercent (главная цифра), residuals[].kind, verdict,
  suggestedStops, transitions, axisSpace ('block' | 'blur.rect' | 'underlay.rect' |
  'layer.rect' — позиции всегда в системе axisSpace, не перепутай), profile
  ('axis'|'columns'|'rays').
  Решение по verdict:
  • «кромки» (kind=edge) — альфа не поможет: правь геометрию (blur.rect,
    w/h блока, кадры) или остановись;
  • «blur-зона» — крути blur.radius и стопы blur.mask;
  • «уровень» — применяй suggestedStops (alpha-таргетам: blurMask/blurBg/
    mask — альфу и #000, цветовым — color);
  • маркеры gradientMissing / blocked:'no-reference' — чини СТАРТ (у таргета
    нет градиента / не загружен референс), НЕ крути стопы;
  • profile:'columns'/'rays' — для дрейфующих каруселей и радиальных зон
    (одна ось-линия слепа к объектам вне линии).
  После PUT жди ~1.5с (debounce) и повторяй GET. Одна ручка за итерацию →
  сравнение профиля → keep/revert; wholesale-резеты запрещены. Перед КАЖДЫМ
  PUT — свежий GET (юзер правит UI параллельно). Откат — `GET /api/journal`
  (200 итераций: поля + zoneMatch/maxErr/verdict до/после).

ШАГ 7 — РУЧКИ (симптом → чем крутить):
  blur.rect (x/y/w/h % блока)          = ГДЕ живёт эффект; граница разгона не там
  blur.radius (px)                     = сила размытия; «перебор/недобор мутит»
  blur.gradient                        = заливка blur-слоя — ОБЯЗАТЕЛЬНА к эффекту
                                         (чистый блюр упирается ~92%); форма:
                                         радиальная тающая от края (cx ≈ 100% rect),
                                         НЕ линейная полоса (даёт вертикальные
                                         полоски по секции)
  blur.mask                            = ФОРМА растворения blur-слоя (ступени/
                                         плавность). Ловушка: середина маски
                                         (α 0.1–0.7) в метрике видна слабо —
                                         финальную форму утверждает юзер глазами
  blur.underlay (rect+цвет/градиент)   = отдельное затемнение ПОД blur, без маски
                                         (::before-конструкция; в кадрах оно
                                         запечено на шаге 2)
  layers[i] (rect + градиент + blend)  = слои поверх базы; layer.rect таскается
                                         и масштабируется на канвасе
  mask                                 = маска на весь блок целиком
  base (цвет/градиент/картинка)        = подложка блока
  stage (checker/solid/image)          = фон канвы; stage.image + stage.isolated —
                                         честная проверка поверх скрина страницы
  Радиус подбирай ДЕЛЕНИЕМ (тренд живой сессии: 65→35.4% zoneMatch, 40→52.5,
  22→74, 14→83.6, 8→91.7). Огромные стартовые радиусы (35–70) — мусор.

ШАГ 8 — СТОП. zoneMatchPercent стабилен 2 итерации, verdict без «уровня»,
residuals только edge (кромки альфой не лечатся) → остановись и отчитайся:
что подобрано, какие остатки остались и почему они не лечатся. Максимум ~8
итераций. Арбитр — глаза юзера, метрика — навигатор.

ШАГ 9 — СДАЧА. `GET /api/state` → собери indented Sass (4 пробела;
-webkit-mask + mask; -webkit-backdrop-filter + backdrop-filter; rect —
4 декларации отдельными строками) + пересчёт в макет: state.export
{scale=2, remBase=10, designWidth=1440}: pxcss = pct/100·блок/scale;
rem = pxcss/remBase; %макета = pxcss/designWidth·100. Отдай юзеру текстом
и перечисли использованные таргеты/пресеты. Юзер видит каждый PUT live в браузере.

ПРАВИЛА:
• если цель — прод-инстанс на Vercel, цикл тот же (поллинг вместо SSE):
  base URL https://<project>.vercel.app, live-отклик PUT ≤10с, analysis?target полли раз в ~5с;
• перед каждым PUT — свежий GET; PUT только полный валидный стейт, не чаще ~5/сек;
• live-обновление видно только при открытой вкладке; кэш сервера переживает reload;
• зум/пан канвы — view-only: на API-координаты не влияют (анализ всегда в системе
  блока/rect), не учитывай их;
• extra-ключи в JSON zod молча вырезает; 400 c issues — читай path;
• npm-registry машины — registry.npmmirror.com (npmjs.org недоступен).
```
