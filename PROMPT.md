# Мастер-промт для агента — подбор blur-затухания в Gradient Lab

> Скопируй агенту целиком. Версия 3 (2026-10-10) — методика v2 (фазы F0–F6
> из `GET /api/methodology`), приборы: hint в анализе, `POST /api/sweep`.

```text
Ты подбираешь blur-затухание / градиентную маску в песочнице Gradient Lab
(локальный клон репозитория gradient-lab, dev-порт 5180). Действуй СТРОГО по
порядку.

ШАГ 0 — ДОКУМЕНТЫ (обязательно, до любых действий).
Прочитай ПОЛНОСТЬЮ API.md из корня репозитория — включая раздел
«Методика подгонки v2». Затем `curl -sf localhost:5180/api/methodology` —
исполняемая процедура F0–F6 (phases + invariants + text) из одного места:
держи её перед глазами всю сессию. Шпаргалка скилла gradient-lab
неполна: таргеты анализа, маркеры, альфа-стопы, журналы живут только в API.md.

ШАГ 1 — СЕРВЕР. `curl -sf localhost:5180/api/schema` — если упал, запусти
dev-сервер в корне репозитория:
`(npm run dev > /tmp/gradient-lab-dev.log 2>&1 &)`.
Рестарт dev-сервера = пустой кэш: восстанови стейт из файла (F6), пустой
стейт не мутируй.

ШАГ 2 — МАТЕРИАЛ = ВХОД методики (ошибка здесь фатальна).
Ровно два кадра ОДНОГО момента анимации, кроп обоих ОДНИМ прямоугольником
(оптимум для краёв экрана — правый/левый квадрат по высоте + запас):
  • base  = блок БЕЗ эффекта (чистый экспорт);
  • ref   = блок С эффектом (из макета).
Все посторонние затемнения/градиенты запеки в ОБОИХ кадрах одинаково — тогда
попиксельный дифф = чистый эффект. Масштаб экспорта учти: пиксели лабы =
физпиксели макета, CSS = /scale (по умолчанию 2x), state.export в стейте.
Перед циклом сохрани полный стейт в файл (state-full.json) — откат и
восстановление только через него.

ШАГ 3 — СТАРТ (F0). `GET /api/state` (404 → шаблон «Минимальный валидный
BlockState» в API.md, или пресет: `GET /api/presets`). Положи кадры:
base.image и compare.refImage (dataURL), compare.x/y=0, scale=1, w/h блока =
точный аспект кропа, export.scale по факту кадров. `PUT /api/state`
(только полный стейт, read-modify-write). НЕТ base.image/refImage →
восстанови из файла, НЕ мутируй пустой стейт.

ШАГ 4 — БОРТ-КОНТРОЛЬ (цикл F0). `GET /api/warnings` — исправь ВСЕ warn ДО
подгонки: аспект-кроп (примени fix {w,h}), трансформ/аспект референса,
«зона blur не накрывает переходы», дубли стопов, нулевой радиус. Повторяй
PUT → GET до cleared (или только info).

ШАГ 5 — ГЕОМЕТРИЯ (F1, вне лабы, без PUT-циклов). Дифф кадров с
предварительным сглаживанием (фотошум):
`convert base.png ref.png -blur 0x2 -compose difference -composite -colorspace Gray`
→ профиль ПО ОСИ эффекта (строки для низ/верх: -resize 'Wx1!'; колонки для
боков: 'xH!'). blur.rect = [onset (>8% max) … 100%], по умолчанию ЦЕЛИКОМ
внутри блока; заход за край — только приём мягкого входа/выхода (легален при
stage.isolated: true). Отдельно посчитай mean-сдвиг base vs ref по зоне =
уровень затемнения Z: Z > 2 уровней → заливка обязательна (F4), Z ~ 0 →
НЕ добавляй заливку по умолчанию. ВЫХОД F1: rect зафиксирован, до F5 не
трогается.

ШАГ 6 — ЦИКЛ ПОДГОНКИ по фазам F2–F5 (какая фаза — знаешь ты; полная
процедура — GET /api/methodology):
  GET /api/analysis?target=<таргет эффекта>   // blurMask | blurBg | underlay | layer:N | blockMask
  Первый ответ может быть 404 {"requested":...} — полли раз в ~1с, пока target
  в ответе не совпадёт с запрошенным (нужна открытая вкладка — SSE).
  Читай: zoneMatchPercent (главная цифра, решения по Δ≥0.5; ±0.3 — шум),
  residuals[].kind, verdict, hint («движение к точке»: готовый переход фазы
  по фактам анализа+журнала), suggestedStops, transitions, axisSpace, profile.
  • F2 РАДИУС — коридор, не деление от большого: photo-кадры 1x–2x → коридор
    8–14px, старт с середины (10–12), шаг ±2–3. Коридор ОДНОЙ КОМАНДОЙ:
    POST /api/sweep {"field":"blur.radius","from":4,"to":20,"steps":6} → {id}
    → полли GET /api/sweep?id=... раз в ~1с до done/aborted → таблица
    value/zoneMatchPercent/maxError. Выход: прирост zoneMatch < 0.5 за шаг →
    радиус ЗАФИКСИРОВАН до конца сессии.
    Sweep умеет НЕ любой числовой лист, а только белый список семейств:
    blur.radius · углы blur.gradient.angle / mask.gradient.angle ·
    альфа стопов base.gradient / mask.gradient / blur.gradient /
    blur.underlay.gradient (stops[i].alpha — α-динамика стопов, подбор маски
    без ручных PUT-циклов) · layers[i].opacity; левый путь → 400.
  • F3 МАСКА — форма: предразогрев 0.1@~35% rect → фронт 0.5@~46 → 1@~58 →
    плато. Ручки: позиции стопов + высота пилота. Метрика честна к середине
    маски, финальную форму утверждает юзер.
  • F4 ЗАЛИВКА — по Z из F1: Z>2 → обязательна (тающая от фронта); Z~0 → одна
    проба тонкой тающей 0.15@0→0@100 после F3: keep если zoneMatch вырос,
    revert если упал.
  • F5 ГЕОМЕТРИЧЕСКИЕ ПРИЁМЫ (если plateau < целевого): по одному,
    keep/revert: rect-заход за край (y −20%, h 120%) · двухступенчатая маска ·
    заливка-вспышка.
  Решение по verdict (если hint не сказал переход):
  • «кромки» (kind=edge) — альфа не поможет: правь геометрию (F1) или стоп;
  • «уровень» — применяй suggestedStops (alpha-таргетам: blurMask/blurBg/
    mask — альфу и #000, цветовым — color);
  • маркеры gradientMissing / blocked:'no-reference' — чини СТАРТ, НЕ крути
    стопы;
  • profile:'columns'/'rays' — для дрейфующих каруселей и радиальных зон.
  После PUT жди ~1.5с (debounce) и повторяй GET. Одна ручка за итерацию →
  keep/revert; wholesale-резеты запрещены. Перед КАЖДЫМ PUT — свежий GET
  (юзер правит UI параллельно; после sweep юзерский ввод = abort — не PUT
  до done/aborted). Откат — `GET /api/journal` или state-full.json.

ШАГ 7 — РУЧКИ (симптом → чем крутить):
  blur.rect (x/y/w/h % блока)          = ГДЕ живёт эффект (зафиксирован в F1);
                                         в F5 допустим заход за край
  blur.radius (px)                     = сила размытия; коридор 8–14 (1x–2x
                                         photo-кадры), фиксация по плато (F2);
                                         коридор — POST /api/sweep
  blur.gradient                        = заливка blur-слоя: ОБЯЗАТЕЛЬНА при
                                         Z>2 (тающая от фронта, радиальная от
                                         края cx ≈ 100% rect, НЕ линейная
                                         полоса); при Z~0 — не добавлять «по
                                         умолчанию», одна проба (F4)
  blur.mask                            = ФОРМА растворения blur-слоя: пред-
                                         разогрев → фронт → плато (F3).
                                         Середина маски в метрике видна
                                         слабо — финальную форму утверждает
                                         юзер глазами
  blur.underlay (rect+цвет/градиент)   = отдельное затемнение ПОД blur, без
                                         маски (::before-конструкция; в кадрах
                                         оно запечено на шаге 2)
  layers[i] (rect + градиент + blend)  = слои поверх базы; layer.rect таскается
                                         и масштабируется на канвасе
  mask                                 = маска на весь блок целиком
  base (цвет/градиент/картинка)        = подложка блока
  stage (checker/solid/image)          = фон канвы; stage.image + stage.isolated —
                                         честная проверка поверх скрина страницы

ШАГ 8 — СТОП (F6). zoneMatchPercent стабилен 2 замера (±0.3 — не прогресс) И
verdict без «уровня» И остатки только blur (≤3 точек) → ОСТАНОВИСЬ и отдай
baseline юзеру: его руки — финальный оптимизатор (2 сессии подряд ручной
вариант бил циклический подбор). Отчитайся: что подобрано, какие остатки
остались и почему не лечатся. Максимум ~8 итераций. Арбитр — глаза юзера,
метрика — навигатор. После каждого PUT сверяй base.image/refImage на месте.

ШАГ 9 — СДАЧА. `GET /api/state` → собери indented Sass (4 пробела;
-webkit-mask + mask; -webkit-backdrop-filter + backdrop-filter; rect —
4 декларации отдельными строками) + пересчёт в макет: state.export
{scale=2, remBase=10, designWidth=1440}: pxcss = pct/100·блок/scale;
rem = pxcss/remBase; %макета = pxcss/designWidth·100. Отдай юзеру текстом
и перечисли использованные таргеты/пресеты. Юзер видит каждый PUT live в браузере.

ПРАВИЛА:
• если цель — прод-инстанс на Vercel, цикл тот же (поллинг вместо SSE):
  base URL https://<project>.vercel.app, live-отклик PUT ≤10с, analysis?target
  полли раз в ~5с, sweep-статус (GET /api/sweep?id=) — раз в ~3с;
• прод — мульти-сессии: работай в СВОЕЙ доске — заголовок X-Lab-Session: <id>
  ([a-zA-Z0-9_-], до 64) на КАЖДОМ запросе; список живых — GET /api/sessions,
  в чужую не пиши; юзеру кидай https://<project>.vercel.app/?join=<id> (его
  вкладка откроется в твоей сессии);
• перед каждым PUT — свежий GET; PUT только полный валидный стейт, не чаще ~5/сек;
• во время sweep (status pending) НЕ ДЕЛАЙ PUT и не правь UI — юзерский ввод
  = abort, исходный радиус не восстанавливается; GET /api/state в это время
  честно отдаёт исходный стейт (транзиентные значения не синкаются); вторая
  sweep-заявка отклоняется (aborted «sweep уже выполняется»);
• короткие сообщения юзеру — POST /api/notify {text: ≤200 симв}: тост в его
  браузере; уведомляй, КОГДА ЗАВЕРШИЛ значимый шаг или всю подгонку, не шли
  на каждую итерацию — это не чат;
• live-обновление видно только при открытой вкладке; кэш сервера переживает reload;
• зум/пан канвы — view-only: на API-координаты не влияют (анализ всегда в системе
  блока/rect), не учитывай их;
• extra-ключи в JSON zod молча вырезает; 400 c issues — читай path;
• npm-registry машины — registry.npmmirror.com (npmjs.org недоступен).
```
